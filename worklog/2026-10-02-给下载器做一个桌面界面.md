# 给下载器做一个能在浏览器里用的桌面界面

## 做了什么

创建了 DouK-Desktop 项目。AntiGravity CLI 负责前端设计和实现：暖白底色、陶土色按钮，三个主要页面是下载、文件、设置。支持粘贴分享文本或具体视频链接、预览、批量加入下载队列、查看真实下载进度、取消重试，以及搜索本地文件。

写了独立的 FastAPI 本地服务，管理队列、文件传输、配置和引擎。浏览器页面与服务都用本地地址，Windows 双击 Start-DouK.cmd 即可打开，Stop-DouK.cmd 可正常关停后台服务和引擎。

代码准备发布到公开仓库 DouK-Desktop。上游引擎、Cookie、下载的视频、任务数据库和本地日志都放在 Git 忽略的运行目录里；原作者源码按版本独立安装，不和界面源码混放。

## 为什么做

原程序需要反复在终端里选择菜单、输入链接。现在希望日常操作能靠一个简洁界面完成，又不因为给项目加了界面而难以跟进原作者更新。

## 值得记住的决策和坑

前端是 React、TypeScript、Vite，桌面服务是 FastAPI，原作者引擎有自己的 Python 环境。界面只使用自己的 API，平台解析继续交给原作者；原作者未来改接口，尽量只改引擎适配层。本次实际验证了 V5.8，未来 6.0 彻底重构时不能假设无条件兼容。

agy 已经登录，最开始没读到可用登录状态的实际原因是 CLI 没沿用 Windows 的系统代理。补上现有代理后复用了保存的凭据，没有重新登录。

Windows 保留了 8765 所在的一段端口，所以正式应用改用 18765；引擎另外选择空闲本地端口，避免暴露到局域网。

V5.8 的设置 API 有两处坑：读配置时遗漏浏览器信息，写配置时却要求这些字段；修改还有只停留在内存的问题。最终采用原子写入私有配置再重启引擎，让画质、Cookie 和客户端对象一起生效。启动失败会恢复旧配置。

取消后立即重试容易让旧队列项误用新的取消信号。队列里保存各自的信号对象，并阻止尚未停止的任务马上重试，避免重复下载或覆盖新状态。未完成的文件单独保存，只有字节数和 MP4 头检查通过后才发布到文件库。当前重试会重新传输文件，未实现断点续传。

前端构建通过，后端 16 项测试通过。用真实抖音视频跑通了预览、下载、取消重试，ffprobe 确认下载到 4K 视频及音轨。设置保存、重启后的历史保留、同版本引擎重装、文件分段访问、凭据不回显，以及 Windows 启停脚本都做了验证。

## 一句话亮点

把需要反复敲终端的抖音下载器，变成了一个好看的本地小工具，界面和下载引擎还能各自更新。
