# 把 Cookie 自动获取接回桌面设置

## 做了什么

设置页增加了浏览器选择、读取浏览器 Cookie、登录后自动获取和取消入口。普通读取支持 Edge、Chrome、Firefox，专用登录窗口支持 Edge 和 Chrome。界面可以显示启动、等待登录、保存、成功或失败状态，获取后自动保存并更新下载引擎。

补齐并锁定依赖，更新 README 和接口约定。新增了中文 AGENTS.md，把用户要求的完成任务后自动提交、推送 GitHub 和核对同步结果记成项目规则，以后完整功能完成时照这个流程执行。

## 为什么做

手工打开开发者工具、复制 Cookie 的流程对日常使用不方便。上游旧浏览器读取入口被停用，且新浏览器的加密或占用会让直接读取失败，因此需要一个用户登录后程序自动保存的入口。用户也要求新增能力及时同步到公开仓库，避免能力只存在于一台电脑上。

## 值得记住的决策、坑和技术点

在桌面桥接层实现，保留上游引擎的独立更新能力。普通读取不提权、不尝试卷影复制；直接读取遇到失败时，用户可以改用专用登录窗口。登录目录独立保存在本机运行目录，后续能够复用。

读取仅保留抖音域名下未过期且带登录会话标记的数据，Cookie 不返回给网页，也不写入日志。独立工作进程支持超时和取消，临时结果处理后清理；保存复用原有配置回滚机制。获取期间阻止新下载、设置修改及引擎更新，避免互相打断。

本机实测普通 Edge、Chrome 读取失败，专用 Edge 窗口登录后自动获取、保存并重启引擎成功，随后平台采集恢复。会话标记存在本身不能保证平台接受，实际采集验证仍然有必要。

后端26项测试通过，前端TypeScript检查和生产构建通过；覆盖域名与过期过滤、秘密不回显、失败保留配置、取消、重复启动和并发操作限制。内置页面自动化连接不可用，界面点击未自动验证；通过真实登录窗口和运行中的接口验证了获取与保存流程。

同步范围是项目源码、文档和依赖；登录状态、配置、数据库及下载转写成果保留在本机。

## 一句话亮点

抖音登录更新可以打开窗口、登录一次、自动保存，新能力完成后也会自动跟上 GitHub。
